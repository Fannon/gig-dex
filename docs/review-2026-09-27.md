# Gig-Dex review — 2026-09-27

The application has useful foundations: local IndexedDB storage, ChordPro
conversion, setlist management, transposition, an offline build, and automated
checks. The most consequential problems were unreliable song fitting and data
loss around editing, migration, and synchronization.

## Fixed in this review

- Bound the song page to the actual dynamic viewport and measure the remaining
  space after its header and controls.
- Search font sizes and column counts together. Choose the largest fitting text,
  preferring fewer columns on ties. Check individual rendered chord/lyric tables
  for both horizontal and vertical overflow, including implicit extra columns.
- Keep sections together where possible, attach labels to their first line, and
  split oversized sections between complete chord/lyric pairs. Refit after
  resizing, font loading, notation changes, chord visibility, and transposition.
- Make manual size changes usable through scrolling when they cannot fit.
  Automatic fitting searches 12–36px; impossible layouts use an explicit 18px
  scroll fallback. Very wide lines can require horizontal scrolling.
- Fix overlapping mobile controls and make the chord toggle's keyboard focus
  visible. Keep the displayed key consistent with transposed chords.
- Restore saved data on Cancel, preserve extended metadata across editor mode
  switches, and reject emptied simple-editor content instead of restoring old
  lyrics during Save.
- Replace the destructive v1-to-v2 database upgrade with a transactional
  migration of songs, metadata, dates, and ordered setlist references. An
  unsuccessful migration rolls back to the original v1 data. This cannot recover
  data already erased by a previous upgrade.
- Store record edit times in Drive metadata and use embedded edit times for old
  uploads. Drive upload time no longer determines which song revision wins.
- Follow Drive listing pagination and ignore files without application identity.
  Validate downloaded record identity, required fields, and dates before saving.
  Failed downloads now report failure without advancing the successful-sync time.
- Add TypeScript checks to fast validation, portable Git hooks, synthetic browser
  regression tests with screenshots, a screenshot gallery/measurement utility,
  and practical visual-check instructions in the validate skill.

## Verification and visual evidence

`npm run verify` covers lint, TypeScript, unit tests, production/PWA build, and
Chromium E2E tests. Migration tests exercise real IndexedDB behavior through
fake-indexeddb, including rollback. Drive tests use mocked HTTP responses;
no live account was connected or mutated during this review.

The baseline sample used six private songs selected across file sizes at five
viewports: 1440×900, 1024×768, 768×1024, 390×844, and 844×390. It found 11 clipped
layouts out of 30. The updated sample found zero clipping, with ten explicit
scroll fallbacks. Synthetic fixtures cover short songs, many sections, one long
section, wide lines, and content that cannot fit on one screen. Browser checks
also cover control changes, resizing, complete line preservation, and reaching
the final line of a scroll fallback.

Private inputs and all generated images/measurements remain in ignored `tmp/`
and `reports/`. No private lyrics or screenshots are committed. The local
reports are `reports/song-layout-before/`, `reports/song-layout-after/`,
`reports/song-layout-synthetic/`, and `reports/song-layout-audit/`. The full
collection audit uses 286 songs and five viewports; consult its `metrics.json`
for the final aggregate results.

## Remaining improvements, in priority order

1. **Implement backup, restore, and ChordPro import.** Settings' import/export
   buttons still show placeholder alerts. Export the complete library, including
   setlists and metadata, and validate restore input before committing it in one
   transaction. Add multi-file ChordPro import with metadata extraction,
   duplicate handling, and clear per-file error reporting. This is the most useful
   next addition for an irreplaceable personal collection.
2. **Make sync deletions and conflicts explicit.** There are no deletion records:
   a locally deleted song that remains on Drive is downloaded again. Introduce
   deletion markers shared between devices before describing sync as a reliable
   backup. Keep competing edits for review rather than relying entirely on
   device-clock timestamps. Add integration tests for two-device changes,
   deletion, and interrupted sync; verify actual OAuth/Drive behavior separately.
3. **Improve long-song reading on small screens.** Wide lines remain unbroken to
   preserve chord alignment, so the readable fallback can scroll horizontally.
   Add word-boundary wrapping that carries chord positions with the lyrics, or
   paginated performance views with clear continuation markers. Expose a minimum
   readable font setting and remember display preferences. Decide whether the
   installed PWA should allow landscape; its manifest currently requests portrait.
4. **Reduce rendering and loading work.** Fitting can test up to 150 candidate
   layouts and runs synchronously before paint. Profile representative long
   songs on an actual tablet; cache intrinsic widths and avoid duplicate fitting
   after size state updates. The production build currently warns about an
   approximately 950kB main JS chunk; ChordSheetJS brings PDF dependencies into
   the build even though the application uses parsing/HTML formatting. Inspect
   named imports and route splitting before adding more eager dependencies.
5. **Strengthen parser and editing error handling.** Recover from invalid song
   markup with a useful error and access to the editor rather than a page crash.
   Add unsaved-change protection for navigation, clearer field validation, and
   tests for malformed imports, unsupported directives, and editor conversion
   round trips. Advanced content's primary metadata and form fields currently
   have separate editing paths; make their precedence clear.
6. **Broaden performance-mode verification.** The browser suite runs Chromium;
   add Firefox/WebKit and installed-PWA/offline checks, then test real touch
   devices, browser zoom, external displays, and font loading. Add a focused gig
   view with setlist navigation, fullscreen controls, and keyboard shortcuts.
   Screenshot bounds checks catch clipping; they do not establish stage-distance
   readability or replace manual image inspection.
